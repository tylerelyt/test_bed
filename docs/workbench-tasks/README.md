# 上下文供应、任务验证与经验复用

[返回项目](../../README.md) · [全部模块](../README.md) · [运行与开发](../../console/README.md) · [参考对齐清单](alignment.json)

这套能力服务于 FDE 的日常工作：组合 Agent 所需的企业上下文，用固定任务验证变更，核对实际结果，再把有效做法整理为可复用经验。测试床是平台中的验证能力，原八个业务模块继续承担索引、检索、推理、工具、图像、训练与监控工作。

各模块上方的“任务与运行记录”包含运行证据、固定任务、批量评测和经验；“上下文工程”模块还提供供应配置。原业务操作保留在下方。

## 完成一次可核对的变更

1. 在原模块运行实际任务。例如在“在线召回排序”查询“机器学习”，核对命中文档和原文。
2. 打开“运行证据”，选择本次记录，查看输入、输出、操作时间线、错误、模型用量及归档产物。
3. 选择“从此运行保存任务”，填写名称、业务验收要点和可执行规则。例如检查“检索结果”包含指定文档，或检查回答中的出处。没有自动规则的任务保留为“尚未评分”。
4. 运行验收规则，并在“人工业务验收”记录实际依据。人工验收通过后，才可将运行设为任务基线。
5. 后续选择固定任务，点击“恢复任务参数”，核对文件、密钥引用、模型和索引状态，再点击原操作按钮。恢复参数不会自动执行业务操作。
6. 修改参数后重跑，比较基线与当前的输入、结果和业务执行耗时。回调返回“请先加载模型”等提示也会如实记录，不能把它当作业务通过。
7. 将核实的做法整理为经验，审阅采用后加入上下文资源。也可以选择多次运行，先生成事实摘要或模型辅助草稿，再人工核对。

## 配置 Agent 可读取的上下文

在“上下文工程 → 任务与运行记录 → 供应配置”维护资源和版本。

| 资源类型 | 用途 | Agent 写入 |
| --- | --- | --- |
| 资料 | 企业事实、材料及来源说明 | 只读 |
| 操作说明 | 岗位做法、步骤和结果约定 | 只读 |
| 工具定义 | 已有工具的名称、说明和输入结构 | 只读，不注册或执行任意代码 |
| 已审阅经验 | 有运行依据的做法、适用条件和反例 | 只读 |
| 角色职责 | 专项角色的目标、边界和交接要求 | 只读，不创建额外 Agent 运行时 |
| Agent 笔记 | 跨会话积累的工作记录 | 仅在资源与配置均明确授权时可写 |

先创建资源，再组合供应配置。配置固定只读资源的具体版本；允许写入的笔记会读取最新版本，并在装配结果中记录实际解析版本。修改资料不会悄悄改变已有配置；升级配置会产生新版本，旧版本继续可读。

默认预算为 **12000 个字符**，可调整。装配优先保留必选资源，超出预算的可选资源会列明未装入原因；必选资源本身超限时直接报错，不截断其内容。这里计量字符，不估算 token。

现有 MCP 服务提供以下入口：

| 入口 | 返回内容 |
| --- | --- |
| `context://catalog` | 资源与配置目录，包含元数据，不加载全部正文 |
| `context://bundles/{配置标识}/{版本}` | 固定配置的资源清单、权限和读取地址 |
| `context://resources/{资源标识}/{版本}` | 资源的具体版本 |
| `discover_context` | 按名称、类型或标签查找配置内资源 |
| `load_context` | 按需装配内容，返回实际版本、字符用量和未装入资源 |
| `write_context_notebook` | 更新已授权笔记，要求当前版本与会话来源 |

笔记更新采用版本冲突检测。两个会话基于同一旧版本写入时，只有一个成功，另一个需要重新读取。来源台账同时记录认证身份及调用方提供的会话标签，后者不作为独立认证身份。版本写入与审计在同一事务中完成。

### 将配置用于固定任务

在“固定任务 → 附加企业上下文”选择配置版本，并指定加入哪个问题或提示词输入，再保存任务新版本。运行时，服务端将选定内容加入这个文本输入，原 Python 函数继续执行。

运行证据同时保留原始任务、实际传入的文本、配置版本、资源解析版本和内容摘要。恢复任务使用原始输入，不会重复拼接。附加内容会影响检索或推理，应先用探针核对；“已交给业务函数”也不能直接证明模型采用了材料，需要结合原模块的实际提示词与输出检查。

停用经验不会回写已经固定的资源版本。需要在供应配置中移除或替换资源、保存新版本，再更新任务或 Agent 所读配置。

外部 Agent 可以通过 MCP 按需读取配置，不需要在平台新建 Agent 绑定。平台不会把全部经验或全部配置自动注入每个 Agent。

任务恢复后，工具栏会显示预设名称与版本；点击“退出任务预设”后，后续原业务操作不再附加该任务的上下文或放行要求。任务被其他页面更新时，旧预设须重新恢复后才能执行。服务重启后，旧运行保留在历史中，页面不会用旧运行的输出覆盖新会话。

## 区分执行、规则与业务验收

| 记录 | 表示什么 |
| --- | --- |
| 执行完成 | Python 回调已返回 |
| 规则通过 / 未通过 | 当前版本的规则检查实际输出后的结果 |
| 无法判定 | 结果缺失、结果被脱敏、评分服务未配置或返回结构无效等 |
| 尚未评分 | 没有配置自动规则 |
| 人工验收通过 / 未通过 | 操作员按业务要求核对后的结论和依据 |

可执行规则包括文本包含、文本排除、精确相等、JSON 必含字段、数值范围，以及可选模型辅助评分。选择某个结果后，可用 `/answer`、`/data/0/0` 等 JSON 路径定位内部字段。空的包含规则不会保存为有效检查。

模型评分只在服务端配置了评分端点和模型后执行，返回结构须包含合法的通过结论、0—1 分数和依据。模型意见与程序规则、人工验收分别保留；它不会自动设置基线或发布配置。

## 固定任务集、参数变体与快速探针

在“批量评测”选择固定任务、配置参数变体和重复次数，可以组合不同模块。每次最多 20 个任务、10 个变体、5 次重复，且总计不超过 100 次运行。所有组合在提交前预检；提交故障或计划单元缺失时，批次不视为完整评测，不能成为基线。

- **检查任务集**：检查重复参数、缺少规则、反例与边界标注、重复次数和模型评分使用情况。显式标签只能辅助检查，不能证明题目的语义覆盖。
- **快速探针**：运行首个任务的所有变体，每组一次，用于先检查配置是否可执行。
- **完整评测**：运行所有任务、变体和重复次数，汇总规则通过率、业务执行 P95 耗时、实际模型用量及成本。
- **任务集版本**：可编辑参数后保存新版本。保持任务与验收规则版本不变时，可以与原基线比较；换了题目或规则后，需要重新核对基线。

任务集中的任务独立运行，不自动编排索引、模型加载或其他数据依赖。应先在原模块准备业务环境。服务端默认最多并行 3 个业务任务，可用 `WORKBENCH_CONCURRENCY` 设置为 1—8；同一模块的业务操作按顺序执行，停止操作使用独立通道，避免加载、推理或训练互相覆盖。

耗时以实际业务执行为主，不把排队与模型评分时间混入参数比较。token 只记录模型接口实际返回的用量；未采集显示为未知。成本基于服务端配置的价格、币种和来源估算，缺少用量或价格时不会填零。

候选建议先比较当前规则通过率；成本完整且币种一致时再比较成本，否则按耗时比较。它只对当前任务和规则成立，仍需结合任务集检查与人工业务验收。用量覆盖不完整时，组成本和 token 汇总保留为未知，成本不参与候选排序。结果可导出 JSON 和 CSV，运行证据还包含事件与产物信息。

## 人工放行、停止与周期验证

固定任务可选择“执行前需要人工放行”。启用后，本次运行会停在“待人工放行”，业务函数尚未执行；允许后进入队列，拒绝会保留未执行记录。普通任务沿用原操作方式。

取消排队任务不会执行业务函数。对正在执行的任务发出停止请求后，仍应核对原模块停止按钮、外部进程、产物及实际终态；Python 无法替代外部训练或桌面系统的终止机制。

周期验证按明确启用的配置运行任务集，可暂停、重新启用并查看上次评测。它固定任务集版本：任务集升级后会暂停，核对后重新启用。服务离线期间错过的周期会合并，上次评测仍在执行时也不会堆积下一次；上次中断或任务、操作版本失效时会暂停并记录原因。暂停影响后续周期，停止当前评测使用“停止本次评测”。

浏览器关闭不会停止服务端任务。刷新页面可续接当前标签的活动运行，事件按游标读取，重复请求不会创建第二次执行。执行服务退出后，未结束记录在下次启动时标为中断，**不会自动重跑业务操作**。

## 密钥、文件与数据保存

密钥可在原输入框按需填写，也可以在固定任务中只保存服务端环境变量名，例如 `DASHSCOPE_API_KEY`。引用由服务端执行时解析，预设、布局响应和浏览器不接收该值。没有配置引用时，恢复任务会将密钥输入留空。

上传文件使用临时引用，不随预设恢复；文件需要重新上传。已完成操作的输出文件可归档到本地，记录大小、SHA-256 和来源运行，服务重启后仍可下载。默认每个文件最多归档 64 MB，可设置 `WORKBENCH_ARTIFACT_MAX_MB`；超限或失败会记录原因，原业务输出继续由模块管理。下载时会校验归档文件。

| 保存位置 | 内容 |
| --- | --- |
| `.workbench/native-runs-v1.sqlite3` | 运行、事件、任务版本、验收、经验、评测与周期配置 |
| `.workbench/context-supply-v1.sqlite3` | 资源版本、供应配置、笔记来源和上下文供应记录 |
| `.workbench/artifacts/` | 已归档产物 |

可通过 `WORKBENCH_STATE_DIR` 指定目录。这些内容不进入 Git。停止执行服务后再备份整个目录；不要让多个执行服务共享运行台账，MCP 服务只使用其中的上下文存储。

原模型目录、图谱、训练产物和业务数据继续由原模块管理，不会被台账替代。参数预设不恢复内部会话状态、已加载模型、随机数状态或外部数据。相同参数版本也不保证结果完全相同，应在验收和经验中登记数据、模型、阶段产物及适用条件。

上下文、运行记录及产物访问按认证项目校验，对话历史另外区分身份与会话；角色和原共享业务边界见[身份与项目权限](../workbench-access/README.md)。业务输入输出和原样文件会留在本地；脱敏覆盖已识别的密码、密钥字段及已知服务端密钥值，不识别所有自由文本中的敏感信息。经验和材料中不要填写密钥。

## 参考项目与采用方式

参考 Anthropic [cwc-workshops](https://github.com/anthropics/cwc-workshops/tree/2c65d16c6de16f8f24117d539a712ea706b5dee7) 的十个项目，按本平台定位适配机制，而非搬入其业务案例或专有托管接口。

| 参考项目 | 采用的工程优点 |
| --- | --- |
| research-desk | 服务端承接任务、有界并发、结构化结果、资源版本、周期验证 |
| production-ready-agent | 可检查事件、任务放行、执行与验收分离 |
| agents-that-remember | 会话与长期记忆分离、共享笔记、经验整理与版本来源 |
| agent-decomposition | 区分确定性业务函数、按需操作说明、角色职责和上下文 |
| eval-driven-agent-development | 固定任务、程序规则、可选模型评分、基线与参数迭代 |
| rightmodel | 先检查题目与评分，再比较通过率、用量、成本和耗时 |
| agent-battle | 声明式配置、小规模探针先于完整运行 |
| ship-your-first-managed-agent | 团队资料只读、笔记授权写入、可下载的文件产物 |
| how-we-claude-code | 机器可读页面状态、异常分支和真实浏览器验证 |
| building-blocks | 文件与内容分开、按需资源发现、批量执行和预算装配 |

证券、并购、值班、游戏和幻灯片生成仍属于参考项目的领域案例。本平台保留企业上下文供应后台定位、八个模块与原 Python 执行逻辑；具体对齐项见[验收清单](alignment.json)。

## 临时资源生命周期

评测单元结束后回收其临时会话；交互会话默认闲置 3600 秒后回收，最多保留 256 个。排队和执行中的任务会固定其会话及文件引用，清理过程不会删除这些资源。

上传默认每文件最多 64 MB，临时总量 512 MB、最多 1000 个文件，未被会话或任务使用的上传默认 3600 秒后清理。已归档产物继续保留供历史下载，未随临时会话清理。配置项为 `WORKBENCH_SESSION_TTL_SECONDS`、`WORKBENCH_MAX_SESSIONS`、`WORKBENCH_UPLOAD_TTL_SECONDS`、`WORKBENCH_UPLOAD_MAX_MB`、`WORKBENCH_UPLOAD_QUOTA_MB`、`WORKBENCH_MAX_UPLOADS`。归档保留期按部署方的数据策略管理。
