# 任务、基线与经验复用

[返回项目](../../README.md) · [全部模块](../README.md) · [运行与开发](../../console/README.md)

这组能力服务于企业上下文的日常维护：把已经跑过的配置保存为固定任务，变更后重跑，检查依据和结果，再把确认有效的做法留给下一次使用。入口位于原八个模块上方的“任务与运行记录”，无需切换到其他管理页面。

## 完成一次变更验证

1. 在原模块填写输入与参数，点击原操作按钮。例如在“在线召回排序”用“机器学习”查询，选择 TF-IDF，核对命中的文档与原文。
2. 展开“任务与运行记录”，选择刚才的运行。记录包含操作、时间、脱敏参数版本、输入和最终输出；流式事件也由服务端保存。
3. 选择“从此运行保存任务”，填写名称和验收要点。例如“应命中包含机器学习定义的文档，能够核对原文”。来源运行已完成时，它会作为初始基线；请先确认实际结果是否满足要求。
4. 后续选择这个任务并点击“恢复任务参数”。页面只恢复可用参数并切到相应子标签，不自动执行。重新上传文件、填写密钥，并准备模型、索引及相关业务状态，再点击原操作按钮。
5. 变更提示词、检索方式或其他参数，运行后选中该记录，点击“与任务基线对比”。页面列出输入、结果和耗时的变化。按验收要点检查实际效果；确认后可将本次运行设为新基线。
6. 在“从此运行提炼经验”中填写适用条件、做法和结论。经验关联来源运行与参数版本，后续可在本模块查看并核对来源。

固定任务保存的是某个操作的参数预设与验收要点。它不编排多个模块，也不自动启动模型、重建图谱、运行训练或操作桌面。

## 运行记录与重连

按钮点击和文本提交在服务端任务中执行，浏览器按事件游标读取输出。页面刷新后，当前浏览器标签的活动任务会重新连接；也可以在运行记录中手动连接本会话正在执行的任务。其他会话的任务可以查看记录，不能接管其内部状态。

关闭页面不会停止 Python 回调。停止训练或生成时，仍使用原模块的停止按钮。服务器进程退出后，未结束的任务在下次启动时标记为“执行中断”。应先核对模型进程、产物、数据写入和桌面实际状态，再决定是否手动重跑。

“执行完成”表示回调已返回，不等于业务任务已成功。回调可能返回“请先加载模型”等提示；这类输出也会如实保留。对比是参数与结果差异，不提供自动质量评分。

## 参数版本与可恢复范围

参数版本根据操作结构和脱敏输入生成。相同参数可关联多次运行，参数变更会产生新的版本；密钥值不会参与可见版本。恢复任务或设置基线时会核对操作结构及直接回调版本，结构发生变化时需重新保存任务。

以下内容不随预设恢复：

- 密码框、带密钥标签的输入，以及从这些输入识别出的密钥值；恢复时对应字段会留空。
- 上传文件和结果文件的临时引用。当前进程的实时输出仍可预览、下载；历史记录只保留文件名，需要重新上传文件。
- Python 内部会话状态、已加载模型、索引或图谱内容、外部服务状态、环境变量和随机数状态。

因此，相同的参数版本不保证结果完全一致。涉及训练、模型输出或外部数据时，还应在验收要点和经验中记录模型、数据来源、阶段产物及适用条件。记录不会自动注入 Agent，也不会把所有会话历史自动变成经验。

## 数据保存

运行、事件、任务预设及经验保存在仓库的 `.workbench/native-runs-v1.sqlite3`，可用服务端环境变量 `WORKBENCH_STATE_DIR` 指定目录。它们不提交到 Git。每个模块的界面显示最近 100 条运行，较早记录仍保存在数据库；已关联的基线和经验来源仍可读取。

“导出运行证据”下载所选运行与当前对比的 JSON。结果和业务文本会保存在本地记录中；脱敏针对已识别的密码与密钥字段，不识别所有自由文本中的敏感信息。填写验收要点与经验时不要放入密钥。数据库面向当前本地工作台实例，未提供跨用户权限隔离。

## 参考实现与采用范围

本轮吸收了 Anthropic [cwc-workshops](https://github.com/anthropics/cwc-workshops) 中几种共性做法：

| 参考做法 | 在本平台中的实现 |
| --- | --- |
| research-desk 的服务端执行与可检查结果 | 独立服务端任务、流式事件、断线重连和运行证据 |
| eval-driven-agent-development 的固定任务与基线 | 任务预设、明确验收要点、参数及结果对比 |
| agents-that-remember 的历史与长期经验分离 | 原始运行记录与人工提炼的经验分别保存，并关联来源 |
| agent-decomposition 的能力边界 | 保留原八个模块和 Python 业务函数，在现有操作上增加记录与验证能力 |

参考仓库是工作坊材料；本平台沿用自己的业务逻辑，没有引入它的任务调度 SDK、研究业务或模型评分规则。
