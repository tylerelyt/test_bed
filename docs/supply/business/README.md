# 原八模块接入统一平台

[返回项目](../../../README.md) · [供应说明](../README.md)

原模块的算法与交互继续复用，数据管理和执行归入新平台。侧栏默认展开“业务处理与验证”，无需去折叠菜单中寻找。

## 归属与实际连接

| 模块 | 归属 | 已接通的供应与运行连接 |
| --- | --- | --- |
| 离线索引构建 | 上下文供应 | 原文与索引功能、图谱审阅保持；运行和文件产物进入统一库，成功输出可发布为上下文；NER 可选择登记模型 |
| 在线召回排序 | 上下文供应 | 保留召回、CTR 与反馈，统一记录输入、结果和产物；结果可发布为上下文 |
| RAG | 上下文验证 | 本次运行可选固定上下文与已登记业务模型，记录实际输入及模型引用 |
| OAG 图谱推理 | 上下文验证 | 保留图谱事实与推理交互，采用相同上下文/模型运行绑定和结果追溯 |
| 上下文工程 | 上下文供应 | MCP、模板和历史继续可用；与岗位发布共用版本化资源库与业务模型供应 |
| 多模态系统 | 上下文与工具验证 | 保留图片与桌面操作，统一作业、事件、文件产物；消息协议的视觉调用可选业务模型，本地视觉模型保留独立配置 |
| 数据回收训练 | 模型供应 | CPT/SFT/DPO 原训练入口保留，冻结原生数据描述及数据快照，保存配置和真实进程日志，成功产物自动登记并关联原运行；偏好与评测同库保存 |
| 系统监控 | 运行管理 | 保留原监控功能；业务执行、调度、停止与产物统一追溯，平台环境页仍报告实际组件安装状态 |

这次没有重写检索、图算法、CTR 或 Harness 循环。组件描述仍使用现有 Gradio Python 定义，浏览器继续由 Next.js 渲染；复用原函数不等于再启动旧 Gradio 网站。

## 执行与存储

```text
Next.js → FastAPI → worker 内业务传输接口（默认 8767）
                      ├─ 原业务函数、会话、事件和评测
                      ├─ CPT/SFT/DPO 原生训练子进程
                      └─ 统一数据库、上下文资源库和模型供应登记
```

API 进程不初始化八模块布局，也不持有它们的内存会话或执行线程池。唯一 worker 拥有这些状态，按原模块队列执行；模块的停止和控制操作有独立通道。岗位 Pi 与文件/部署作业仍有各自队列，不需要新增集群组件。

原 `native-runs-v1.sqlite3` 中的运行、任务、经验、任务集、评测批次、周期任务、文件元数据和事件，首次启动时完整复制到 `business_records`、`business_events`，保留原 ID、版本与项目归属；原文件和 `.pre-platform.bak` 留作备份。后续生产服务只写统一数据库，旧 `/api/native/*` 保留为传输别名。

重启中断记录不会自动重跑。原图谱、索引、CTR 数据和大模型权重继续按各自存储接口保存，不把图数据库搬进关系表，也不复制巨型权重。备份须包括数据库、工作目录和实际登记的权重路径。

## 操作方法

- 在业务页展开“本次操作使用的供应配置”，选业务模型，以及要附加的上下文和输入字段。只有消息协议调用采用所选模型；CTR、本地图像模型不随此选择变化。
- 点击原操作按钮后，在“作业管理”可以看到该业务运行，查看结果、实际模型、上下文来源与文件产物；详细事件回放仍在模块运行记录中。
- 成功完成的输出可以点击“发布输出为上下文资源”，再到上下文供应组合岗位配置。失败或没有输出的运行不能发布。
- 原 CPT/SFT/DPO 训练的 JSON 数据及原生列映射先固定保存，再启动 LLaMA-Factory。成功且产物文件有效时登记模型；缺少权重或登记失败会明确记录 `artifact_error`，不会把空目录当成模型。
- 训练数据、产物可在“模型供应”统一查看。业务训练的适配器可以继续合并导出、部署和用于岗位候选版本；仍须核对实际模型质量。

## 验证范围

自动化检查覆盖旧流程在统一仓储下的回放、评测、基线、周期任务和权限；八模块测试回调验证同一模型与上下文绑定、作业汇总和输出发布。浏览器覆盖原业务进入统一作业并发布上下文。

原 CPT、SFT、DPO 适配器各使用本机微型 Llama 权重和 8 条样本实际训练成功，记录产物 ID。此证据证明连接与原生执行，不证明企业任务效果；桌面动作、付费模型与 vLLM 实机部署仍需对应环境进行业务验收。

本轮本机验证结果：104 项后端测试、12 组浏览器交互、41 项原回调检查全部通过；最小依赖环境验证了 API 与独立业务 worker 可启动且不提前加载 Gradio/Torch。测试使用独立状态目录，原生训练使用微型测试权重，不调用付费业务模型。
