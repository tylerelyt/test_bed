# 供应配套改造验收

## 2026-11-14 入口归属与作业边界

原索引、召回、RAG/OAG、MCP 与图片资料归上下文供应；训练评测和图像生成归模型供应；桌面 Agent 及系统监控分别归岗位 Agent 与运行环境。原代码、数据和交互保留，侧栏不再设平行的旧模块分组。图片资料、图像模型和桌面 Agent 只展示各自功能及运行历史。

作业列表只读取实际供应作业，移除将旧回调改名为 `business:` 作业的适配器，包括详情和取消的转发。主站原列表的 200 条旧回调全部不再混入；对应数据库记录保留。后台接口测试覆盖真实导入的提交、取消、历史保留及拒绝伪作业标识；浏览器覆盖能力归属、多模态拆分、旧入口恢复、记录筛选和原有任务流程。

本轮不改训练或检索算法，也没有重新验证模型质量、vLLM 或真实桌面执行。

## 2026-11-14 服务边界纠正

原文档读取 → 资料版本 → 固定倒排索引 → 岗位发布包 → 原生 Pi 检索工具，已在主站 PostgreSQL 和独立 worker 上跑通。修改原资料后，固定索引仍返回旧版本。实际图服务读取到 15 条关系，快照前后顶点数与边数一致。

后端 112 项、浏览器 13 组、前端生产构建及原回调 41 项读取/输入校验通过。模型供应分别实际执行 CPT、SFT、DPO，成功登记产物，训练服务进程没有导入 Gradio 或旧回调运行时。微型权重和本地协议模型只证明执行链，不证明企业业务效果。

已撤除通用 SDK 替换、任意界面输入覆盖及输出 JSON 发布；不能再以统一运行记录证明原八模块全部服务化。[接入边界与未完成范围](../../architecture/service-contracts/README.md)。vLLM 仍未实机验收。

启动与退出实测发现并修复了两个问题：信号处理器调用 `Event.set()` 可能重入非重入锁，造成旧 worker 退出死锁；启动脚本只检查标识文件存在，可能把旧 PID 当成本次进程。现在信号处理器仅设置退出标记，进程关闭时再停止队列与原生进程；脚本核对本次子进程 PID 并等待已启动子进程退出。
