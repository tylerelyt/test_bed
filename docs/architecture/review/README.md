# 当前架构审查

日期：2026-11-13。对象：[单机架构方案](../README.md)。这是设计审查，尚未验证实现或完整组件联调。

## 本轮架构判断

1. **平台内部职责**：明确岗位管理、上下文供应、模型供应、Agent 装配发布、运行管理五个模块，各自拥有数据与业务规则，可放在同一个后端中；避免用一个 FastAPI 大框掩盖平台自身设计。
2. **三种供应的交付约定**：上下文模块交付上下文包及读取接口；模型模块交付可调用的模型服务配置；Agent 装配模块消费二者并生成 Harness 原生发布包；运行管理消费发布包。职责与依赖可以按一次真实岗位任务检查。
3. **平台与 Harness 的责任**：平台处理配置、版本和本机进程管理；Harness 执行实际循环。配置适配与运行适配分别定义，不要求各 Harness 内部结构一致。
4. **复杂度范围**：单机、单个后台作业进程、本地持久目录；撤回首版 RabbitMQ、Celery、SeaweedFS、跨主机接管及 HA 设计。独立进程用于避免业务请求被长任务阻塞，不表示已经拆分微服务。

## 尚待实际接入确认

- 首个 Harness 的精确版本、可用模型及模型协议。
- 首个岗位的职责、必要资料、可用工具和一组验收任务。
- 原生配置加载顺序、事件终态、中断和会话保存行为。
- 自有模型涉及的实际 GPU 与数据规模。

上述内容影响具体适配与容量，不作为提前引入集群的理由。模块接口应通过第一条真实任务链验证，不能仅凭设计稿认定已经成立。

## 先前审查的处理

[最初的运行层审查](../history/initial/review/README.md)偏重执行可靠性。请求去重、版本记录、基本权限和目录隔离保留为单机正确性要求；跨主机接管、执行租约和 HA 不作为本轮实施前提。
